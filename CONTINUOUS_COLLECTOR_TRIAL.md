# Controlled server trial: research only

Do not turn on automatic trading. This collector makes public read-only requests.
It uses *static* candidate and token mapping files: refresh and review them
before each trial; expired markets and mismatched settlement rules are possible.

## Prerequisites
- Python 3.11 and the repo checked out on the intended server
- Real `research_matches.json` and `opposing_token_map.json` generated by the
  existing market discovery workflow and reviewed for their provenance
- Confirm exchange API terms/rate limits and available disk space first
- Keep this process separate from the Kraken scanner

## Small trial (only one sampling cycle)

```bash
python -m unittest discover -s tests -v
python continuous_book_collector.py --matches research_matches.json --mapping opposing_token_map.json --output-dir local_market_archives --max-pairs 3 --workers 1 --interval-seconds 60 --iterations 1
python collector_health.py --archive-dir local_market_archives
python local_historical_backtest.py --archive-dir local_market_archives --output-dir local_backtest_output
```

If successful, evaluate request latency, timestamp spread, errors, refresh
frequency, and API limits. Only then consider a bounded 10-cycle trial at
`--max-pairs 5 --workers 2 --iterations 10`, followed by further expansion.

No background service is installed or started by this guide. An ordinary
collection loop will stop after its specified number of iterations. Archive
files are append-only; monitor their storage and backups. Local replay results
are modeled candidate observations, not executable arbitrage or realized P&L.
